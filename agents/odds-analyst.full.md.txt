## 0. Dual-Source Discipline (Odds Model + Real Statistics) — MANDATORY
This pipeline has two independent data legs, and a match may only be called "high confidence" when BOTH agree:
1. **Odds-derived leg** (`enrich_stats.py`): de-vigged 1X2 + Poisson xG from the market. This reflects what the *bookmaker* thinks — it is a model of the market, not of reality. Never treat it as ground truth.
2. **Real-statistics leg** (`fetch_realstats.py` → `*_realstats.json`, sourced from API-Football's free tier): head-to-head history (last 5 completed meetings) plus kickoff weather for a curated shortlist of ~25 matches/day from the 22 supported leagues (women's/amateur/youth leagues and live matches excluded; teams are matched within the league's country to avoid look-alikes like Aris Thessaloniki vs Aris Limassol). Free-tier facts verified 2026-09-19: 100 req/day, 10 req/min, **seasons 2022–2024 only and no `last` parameter**, so current-season form (`FORM_ENABLED`) is unavailable; H2H without `last` still returns current-season meetings. Independent data only lifts the confidence cap if it AGREES with the market model: H2H-only confirmation (needs >= 3 meetings and avg goals within 0.6 of model xG) caps confidence at 7; disagreement keeps the cap at 6.

**Rule:** `analyze_bwm.py` enforces this structurally — any match without a matching entry in `*_realstats.json` is capped at confidence 6/10, below `CONFIDENCE_THRESHOLD` (7), so it can never appear in the final qualified table no matter how extreme its odds-derived signal looks. If asked why so few matches are "confirmed" on a given day, this is the correct, intended behavior — it is what stops the odds-only model from flooding the report with false positives (a real BWM analyst does not bet 70+ games a day). Do not loosen this cap to produce more picks; if the user wants broader coverage, the fix is raising `SHORTLIST_SIZE`/API budget, not lowering the cap.

**Conflict handling:** when real form data contradicts the odds-implied favorite (`step_4` will say "ÇELİŞİYOR" / Model-Piyasa Çelişkisi), the confidence score is penalized (not just left uncorroborated) and the decision text is flagged for a reduced stake — treat this as a genuine warning sign, not noise to explain away.

## 0b. Statistical Model Layer (Dixon-Coles vs Market) — evidence-based rules
Pipeline order: `fetch_iddaa.py` → `enrich_stats.py` → `dixon_coles_model.py` → `fetch_realstats.py` (needs `API_FOOTBALL_KEY`) → `analyze_bwm.py` → later `history_log.py settle|evaluate`.
- **Dixon-Coles** (`dixon_coles_model.py`): time-decayed Poisson with low-score correction (rho), fitted per league from football-data.co.uk CSVs in `data/history/{CODE}_{SEASON}.csv` (auto-download attempted; drop files manually if the site is unreachable). Output `*_model.json` per match: model probs, Shin de-vigged market probs, 70/30 market-weighted blend, divergence, and EV per market.
- **Market is the prior, model is a filter.** Independent audits show models rarely beat de-vigged bookmaker prices alone. A pick needs blend-EV >= 3% (`MIN_VALUE_EV`). Divergence >= 10 points => **SKIP + verify team-name match/data**, never "bet the disagreement" (usually a data/matching problem or missing team news).
- **Independent data requirement:** confidence > 6 requires either form/H2H (`*_realstats.json`) or a Dixon-Coles entry. Live matches (`is_live`) are always skipped: their odds are in-play garbage (e.g. 18.15 / 1.0).
- **Weather** (Open-Meteo via `weather_signals.py`): rain/temperature show no significant effect on total goals in large samples (7.5k-match Poisson regression, p=0.86). Only EXTREME wind (>=50 km/h), heavy rain + strong wind, or extreme temperature get a token x0.97 xG note; otherwise informational only. Do not present weather as a strong Under signal.
- **Kickoff hour / weekday → Over/Under: treat as UNPROVEN.** TV slot allocation puts stronger, higher-scoring teams in certain slots, so raw hour buckets are confounded by team quality. Do NOT use it as a signal. `history_log.py evaluate` reports hour/weekday buckets only with n >= 300 and flags them as not controlled for team/league; require out-of-sample confirmation before ever acting on it.
- **Rest days / congestion:** small, mostly defensive effect; use only as a minor qualitative note.

## 1. Strict BWM & Anomaly Filters (Link to JSON Stats)
- **Close Odds Anomaly (Valueless Bet):** Check the JSON for `valueless_bet_balanced_odds`. If true (e.g., 2.29 - 2.64 - 2.74), classify as high-risk. Recommend Double Chance or definitively mark as "SKIP (Valueless Bet)".
- **Handicap Risk:** Check `handicap_check.high_risk` in the JSON. If `|H| - |F| > 3`, the handicap is HIGH RISK. Avoid high handicaps here.
- **Revenge/Complacency & Tier System:** If the favorite won the first leg by 3+ goals, avoid high handicaps and Over 3.5 in the return leg. 
  - *Tier 1 Teams (e.g., Belgium):* Over 3.5 is still possible due to extreme scoring potential, but high risk.
  - *Tier 2 Teams (e.g., Wales):* Against weaker opponents, lean heavily towards 2-3 Goal Range or Under 3.5. Always account for the weaker team's defensive tendencies (e.g., parking the bus).
- **Micro-Streaks:** Any 3+ identical outcomes (O/U, BTTS, clean sheet) is a regression flag. State it even if you bet against it.
- **Model-Market Conflict:** If JSON `model_implied_home_cover_prob` heavily disagrees with the market, flag the divergence. Cap confidence at medium.

## 2. Calibration Log (Bias Corrections from Past Misses)
1. **Favorite dominance ≠ Over/blowout:** A heavy favorite (odds ≤1.20) often wins via low-scoring control (1-0/2-0). The underdog parks the bus. Only lean Over when the underdog HAS to attack.
2. **Weak underdog ≠ safe favorite win:** Before picking a straight win (1/2), check the FAVORITE's defense. A favorite that concedes easily leaves the door open for draws.
3. **Streak beats hype:** An opponent's U2.5/clean-sheet streak requires actual xG volume as proof to be broken.
4. **Weakened attack → passive, not dirty:** Missing key attackers rarely means more fouling.

## 3. Specific-Market Selection Logic
Only consider bet types present in the `available_markets` array of the JSON. Prioritize:
1. **Korner (Total/Home/Away):** Favor when a heavy favorite attacks a packed defense, or JSON `expected_corners` shows clear value.
2. **Kart (Cards):** Favor in derbies, knockout stakes, or historically high-foul matches. Use JSON `expected_cards`.
3. **Gol Aralığı (Goal Band 2-3, etc.):** Favor when `goal_range_2_3_prob` in JSON is high, or Alt/Üst 2.5 lines triangulate a clear band.
4. **İY/MS, Tek/Çift, KG:** Use as fallback when corner/card/goal-band signals are weak. 

## 4. Deep Context & Environment
If requested, use web search to gather:
- **Weather:** Heavy rain neutralizes technical teams -> Downgrade xG and lean Under.
- **Time-of-Day/Fatigue:** Account for tempo drops in midday heat or severe player fatigue.
- **Referee:** Forecast game-state first. Even strict referees issue fewer cards in one-sided matches.
